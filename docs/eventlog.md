# 战斗日志格式（v1）

每次游戏（进程）写一份：`%APPDATA%\Brotato\CombatTracker\logs\bct-yyyyMMdd-HHmmss.bctlog.gz`。
写的过程中是纯文本 `.bctlog`，每 2 秒追加一次；正常退出时写 `#END`、压成标准 gzip 并删掉文本版，
上次没压成的（游戏被强杀）下次启动时补压。解压后一行一个事件。保留天数见配置项 `LogRetentionDays`。

**日志记录的是事件，不是统计结果。** 分段、归因到行、分桶都由解析器（`core/parser.gd`）从事件算出来，
实时统计和导入日志走的是同一个解析器。所以：

- 面板上实时看到的数字，和日后导入这份日志看到的数字逐项一致（自动测试每次都逐段、逐来源核对）
- 解析器以后加了新维度、改进了分类规则，旧日志重新导入也能按新规则算

## 文件结构

```
#BCTLOG|1
#META|mod=0.1.0|game=1.1.15.4|start=2026-09-28T20:29:31|start_unix=1790598571
0.000|W|start|9|0|1|1790598576
0.000|C|0|character_well_rounded
0.000|L|0|w:weapon_torch:1,w:weapon_plank:1,w:weapon_plank:1,w:weapon_knife:0
2.283|D|0|w:weapon_shredder:0|e:chaser|5|5|0|x|stat_ranged_damage
…
29.867|W|end|0
#END|events=674
```

- 第一行 `#BCTLOG|版本号`。读的时候没有这一行就不认作战斗日志。
- `#META` 是键值对：`mod` 本 Mod 版本、`game` 游戏版本、`start` 开始的本地时间、`start_unix` 同一时刻的 Unix 时间。
- `#END` 是正常退出时写的结束标记。没有它说明游戏被强杀或还在写——读到哪算哪，主面板会提示「末尾不完整」。
- 其它以 `#` 开头的行是注释。

## 事件

每行第一个字段是**波次时钟**（秒，开波清零，游戏暂停时不走，保留 3 位小数），第二个是事件字母，后面按类型解释。
空字段表示「不知道」。文本字段里的 `\`、`|`、换行分别转义成 `\\`、`\p`、`\n`。

| 字母 | 含义 | 字段 |
|---|---|---|
| `W` | 波次信号 | `start` `波次` `标签` `局序` `开始时刻`；`end` `标签`；`tags` `标签` |
| `C` | 玩家的角色 | `玩家` `角色 id` |
| `L` | 开波时玩家的武器 | `玩家` `武器键,武器键,…` |
| `D` | 对敌人造成的伤害 | `玩家` `来源` `目标` `数值` `有效值` `标志` `形式` `类别` |
| `T` | 玩家受到的伤害 | `玩家` `攻击者` `数值` `有效值` `标志` |
| `H` | 玩家获得的生命恢复 | `玩家` `来源` `数值` |
| `R` | 玩家手动重置（F10 / 浮窗上的「重置」） | — |
| `P` | 联机队友这一波的统计快照 | `玩家` `快照（JSON）` `波次` |

字段说明：

- **玩家**：玩家序号，`0` 起，即游戏里的 P1–P4。
- **标签**：位标志，`1` Boss 波、`2` 精英波、`4` 怪潮波、`8` 无尽模式。`start` 时知道多少写多少，Boss 出场时再补一条 `tags`，`end` 时写最终值。
- **局序**：本次游戏里第几局。换角色、回过标题、波次倒退、没失败又重打同一波（从暂停菜单重开）都算新的一局；
  同一波失败后重来算同一局，解析器据此给标题加「#2」。
- **开始时刻**：开波时的 Unix 时间，主面板列表里的「20:29」由它换算。
- **来源 / 目标 / 攻击者**是不随语言变的键，显示名在导入时按当时的游戏语言现查：

  | 键 | 含义 |
  |---|---|
  | `w:<weapon_id>:<品质>` | 武器，品质 0–3 对应 I–IV，如 `w:weapon_smg:2` 是冲锋枪 III |
  | `i:<id>` | 物品 / 角色 / 其它带追踪键的来源，`id` 即游戏里的 `my_id`，如 `i:item_turret`、`i:item_riposte` |
  | `m:<enemy_id>` | 被魅惑的敌人 |
  | `e:<enemy_id>` / `b:<id>` / `l:<id>` | 普通敌人 / Boss / 精英 |
  | `n:tree` | 树（仅 `IncludeTrees` 打开时出现） |
  | `p:self` | 自身效果造成的伤害（没有命中框也没有来源的扣血） |
  | `h:regen` / `h:lifesteal` / `h:hot` / `h:consumable` | 生命再生 / 生命窃取 / 持续恢复 / 消耗品 |
  | `o:burn` / `o:explosion` / `o:effect` / `o:unknown` | 归不到具体来源的燃烧 / 爆炸 / 效果伤害 / 未知 |

- **数值**：游戏 `took_damage` 信号里的伤害值——输出是含溢出的结算伤害，承伤是护甲后的伤害（闪避、抵挡为 0）。
- **有效值**：实际扣掉的血量。输出的击杀那一击扣掉溢出，其余等于数值。面板默认按有效值算（配置 `CountOverkill`）。
- **标志**：`D` 行 `1` 暴击、`2` 击杀、`4` 秒杀；`T` 行 `1` 闪避、`2` 抵挡（护盾类效果）、`4` 护甲起了作用、`8` 这一击后阵亡。
- **形式**：`h` 直接命中、`b` 燃烧跳伤、`x` 爆炸、`e` 效果（反击、敌人死亡 / 拾取触发的属性伤害等）。
- **类别**：命中框（燃烧是燃烧数据）的第一个缩放属性，如 `stat_melee_damage`、`stat_elemental_damage`、`stat_engineering`，没有为空。
- **快照**：`P` 行是一名队友在一波里的全部统计（JSON，结构见 `core/parser.gd` 的 `export_snapshot`）。
  联机时每 2 秒收到一次，只在收波时（以及收波后迟到的最终版）写进日志；同一波的后一条覆盖前一条。

## 兼容规则

- **只加不改。** 已发布的字母和字段含义永远不变。新信息用新的事件字母，或者在已有行的**末尾**追加字段。
- 读的一方遇到不认识的事件字母就跳过（计入「不认识」），多出来的字段忽略，缺的字段按「不知道」处理。
  所以旧版本能读新日志（只是看不到新信息），新版本能读旧日志（新维度在旧日志里为空或按旧规则推算）。
- 行格式不兼容的改动才升版本号。解析器对更高的版本号照读不误，只是按自己认识的部分解析。

## 加一个统计维度

1. 需要的原始信息日志里已经有了（比如「对 Boss 的伤害占比」——`D` 行里有目标，Boss 的目标键以 `b:` 开头）：
   只改 `core/parser.gd` 和界面，旧日志导入就能看到。
2. 日志里还没有：在记录端（`game/tracker.gd`）把原始信息加进事件，按上面的兼容规则扩展格式，再改解析器。
   之后写的日志就有这项数据。

## 离线查看

日志是标准 gzip，任何工具都能打开：

```bash
python -c "import gzip,sys; sys.stdout.write(gzip.open(sys.argv[1],'rt',encoding='utf-8').read())" bct-20260928-202931.bctlog.gz
```
